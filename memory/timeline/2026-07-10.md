## Paste-a-link job listing import → Apply & Optimize

Built the owner-requested "add a job from any link" feature (pre-cursor to a future Chrome extension). Users paste any listing URL (Indeed/LinkedIn/Greenhouse/careers page); `api/import-listing.js` fetches server-side with per-hop DNS-validated redirects (SSRF-safe), extracts via schema.org JobPosting JSON-LD → og/meta+title heuristics → ATS URL slug, upserts through the existing `upsertJobs` path (company created too), and returns the UI-shaped job. Jobs page gained a "Paste the link" entry that drops the imported listing straight into ApplyOptimizeModal — whose done-step "Apply Online →" links back to the original listing URL (the requested round-trip). Verified before writing: prod `jobs` schema + indexes via SQL — `jobs_uniq(title,company,location)` exists, so a conflicting insert returns 0 rows and the handler falls back to surfacing the aggregated duplicate; imports dedupe by `apply_url` first. Bot-walled pages (Indeed 403s) return `needs_details:true` and the modal asks the user for title/company — never guessed. Thin imports stay honestly unrated (score null). 19 new unit tests; suite 304/304; build green; handler exercised end-to-end with canned network (happy/bot-wall/manual/SSRF/re-import/conflict/405). NOT verified from sandbox: real external page fetch (egress proxy blocks job boards). New rate-limit bucket import-listing:20/hr; vercel.json maxDuration 30.
